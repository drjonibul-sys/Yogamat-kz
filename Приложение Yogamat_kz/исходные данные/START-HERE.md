# Йога-практика — независимая копия версии 10

Это копия исходного браузерного приложения из архива от 14 ноября 2026 года. Исходные файлы и готовый PWA-сайт сохранены без изменений. Конфигурация `.openai/hosting.json`, указывающая на существующий сайт, не включена, чтобы исключить случайную публикацию поверх оригинала.

## Быстрый запуск

* Папка `dist/` — готовый сайт. Разместите всё содержимое на собственном HTTPS-хостинге с сохранением каталогов.
* Для локальной проверки из `dist/`: `python3 -m http.server 8080` и открыть `http://localhost:8080` на компьютере. Service Worker/PWA нужно проверять отдельно на HTTPS.
* Для пересборки офлайн-кэша после изменений в dist: из корня проекта запустите `python3 build-pwa.py`.
* Проверки: `node tests/practices-check.cjs`, `node tests/catalog-check.cjs`, `node tests/pwa-check.cjs`, `node tests/pwa-ui-check.cjs`, `node tests/income-check.cjs`, `node tests/rent-check.cjs`.

## Персональные данные

Персональные записи клиентов, платежей и аренды не входят в исходный архив; их нужно экспортировать из исходного приложения (Настройки → Сохранить копию в файл) и импортировать в новую копию. Не удаляйте оригинальные данные браузера до успешной проверки импорта.

## Ограничения

Все восемь наборов тестов выполнены в Node.js успешно 17.11.2026. Развёртывание на удалённом хостинге и установка на физическое устройство пока не проверялись.

## Настройки → Обновления приложения (добавлено 14.11.2026)

* В шестерёнке (раздел архива/настроек) доступны адрес источника, переключатель автоматической проверки, «Проверить обновления» и «Установить обновление».
* Проверка идёт при запуске и возвращении в приложение (не чаще раза за 6 часов), либо вручную. Нужен `app-update.json` и актуальный `sw.js` в каталоге приложения. Файл метаданных автоматически создаётся `python3 build-pwa.py`.
* Установка доступна **только с текущего origin и того же пути установки PWA**. Можно изменить адрес источника для проверки другого сайта, но браузер не позволяет чужому Service Worker перезаписать приложение, установленное по другому адресу. Для такого обновления необходимо сначала опубликовать сборку на текущем HTTPS-хостинге.
* Новая версия целиком загружается в отдельный кэш, после чего отображается подтверждение. При согласии активируется новый Service Worker и приложение перезагружается. При отказе старое приложение продолжает работу.
* Клиенты, посещения, оплаты, аренда, пользовательские настройки и локальные резервные копии **не входят в сборку** и не очищаются при обновлении. Перед подтверждением приложение пытается создать внутренний снимок; рекомендуется также экспортировать JSON в «Файлы».
* Не очищайте данные сайта/браузера и не переносите PWA на другой домен, рассчитывая на автоматическое сохранение записей: в таких случаях понадобится отдельный экспорт/импорт JSON.
* Обновления выполняются **в кэше клиентского приложения**, но не загружают файлы на сервер самостоятельно. Для выпуска очередной версии требуется публикация изменённых файлов `dist/`.

Дополнительная проверка: `node tests/update-check.cjs`.
