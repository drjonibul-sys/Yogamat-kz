# Вход по e-mail (версия 2.0.0)

При открытии приложения через сайт (HTTPS) вход выполняется по адресу электронной почты и одноразовому коду из письма. Роли (администратор, тренер) и список разрешённых адресов хранятся в Supabase Free. Клиентская база на сервер не отправляется и остаётся на устройстве.

Если Supabase не подключён, приложение работает как раньше: локальный вход по PIN (см. `ROLES.md`).

## Как это работает
1. Пользователь вводит e-mail. Приложение проверяет адрес в списке (`email_allowed`), только потом просит Supabase отправить письмо с кодом. Чужим адресам письма не отправляются.
2. Пользователь вводит код из письма (6–8 цифр). Ссылки в письмах не используются: ссылка открылась бы в браузере, а не в установленном приложении, где хранилище отдельное.
3. Роль и имя берутся из таблицы `allowed_emails`. Сеанс хранится на устройстве.
4. Без интернета приложение работает по сохранённому сеансу до 7 дней после последней проверки; затем нужна проверка в сети. Проверка выполняется при запуске и при появлении сети (не чаще раза в 12 часов).
5. Если администратор отключил или удалил адрес, доступ закрывается при ближайшей проверке с интернетом. Данные на устройстве тренера не удаляются (сервер ими не владеет).
6. Администратор ведёт список адресов в Настройки → «Пользователи и роли» (добавить, изменить роль и имя, отключить, удалить). Себя отключить или удалить нельзя.

## Настройка (один раз)
1. Создайте проект на supabase.com (план Free).
2. Authentication → Providers → Email: включить. **Confirm email** можно оставить включённым.
3. Authentication → Email Templates → **Magic Link** и **Confirm signup**: в тексте письма замените ссылку на код: `Ваш код для входа: {{ .Token }}`. Без этого письмо придёт со ссылкой, а не с кодом.
4. Authentication → Settings → Email OTP Length: 6 (по умолчанию 6 или 8; приложение принимает 6–10 цифр).
5. **Почта.** Встроенная почта Supabase даёт только несколько писем в час и не подходит для постоянной работы. Подключите свой SMTP (Authentication → SMTP Settings): например Resend, Brevo, Mailgun, Gmail SMTP с паролем приложения.
6. SQL Editor: выполните `supabase-email-auth.sql`, подставив в конце свой адрес администратора.
7. Project Settings → API: скопируйте **Project URL** и ключ **anon public**. Ключ `service_role` в приложение вставлять нельзя.
8. Подключите проект к приложению одним из способов:
   - Файл `auth-config.js` (рекомендуется): впишите `url` и `anonKey`, затем опубликуйте приложение на хостинге (см. `HOSTING.md`);
   - либо в приложении: войдите по PIN администратором → Настройки → «Вход по e-mail» → вставьте адрес и ключ → «Сохранить» (действует на этом устройстве, вступает в силу при следующем открытии через сайт).
9. Откройте сайт, введите адрес администратора, получите код, войдите. Остальные адреса добавляйте в Настройках.

## Безопасность
- Anon-ключ публичный по замыслу Supabase. Список адресов защищён правилами RLS: читать могут только разрешённые, менять — только администратор.
- Проверка `email_allowed` позволяет узнать, есть ли адрес в списке (перебор адресов). Если это неприемлемо, отключите её в коде (`auth.js`, метод `requestCode`) и закройте регистрацию в Supabase: Authentication → Sign In / Providers → отключить «Allow new users to sign up», создавая пользователей вручную.
- Роли работают на уровне интерфейса. Данные хранятся в браузере устройства без шифрования, поэтому владелец устройства технически может их прочитать. Для переноса и хранения копий используйте зашифрованный формат (см. план миграции).
- Вход по e-mail включается только при открытии через HTTPS (или localhost для проверок). В просмотре внутри Claude, в локальном файле и без настроенного проекта работает вход по PIN.

## Что проверено
Тестовый сервер, имитирующий Supabase (`tests/mock_supabase.py`, сценарий `tests/browser/v5-email.py`): неизвестный и неверный адрес, неверный и верный код, роль и имя, список адресов и его изменение администратором, запрет изменений для тренера, выход, сохранение сеанса, отключение доступа, срок работы без сети (8 дней — вход закрыт, 2 дня — открыт). С настоящим проектом Supabase, реальной почтой и на iPhone/iPad проверок не было.
